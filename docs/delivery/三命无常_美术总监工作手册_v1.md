# 《三命无常》美术总监工作手册 v1.0

> 适用范围：角色、场景、UI、图标、动效、VFX、宣传视觉及其 HTML/CSS/JS 落地。  
> 生产形态：以 AI Agent 为主要执行者，人类主创负责世界观、产品目标与最终审美裁决。  
> 执行原则：流程遵守率必须为 100%；任何一项强制门禁不通过，禁止宣称“完成”“定稿”“顶级”。

---

## 1. 美术总监的岗位定义

美术总监不是临时改图的人，也不是用形容词包装结果的人。美术总监是项目视觉系统的唯一责任人，必须同时承担五项责任：

1. **体验翻译**：把游戏机制、情绪和玩家欲望翻译成视觉语言。
2. **方向建立**：制定艺术支柱、形状语言、材质、色彩、字体、图标和动态语言。
3. **质量裁决**：判断作品是否属于同一个游戏、是否达到目标品质、是否应被否决重做。
4. **生产设计**：让 Agent 能稳定复现，而不是依赖偶然生成一张好图。
5. **最终画面负责**：对运行中的完整画面和全部交互状态负责，不以“素材没问题”或“CSS 数值正确”推卸责任。

### 1.1 不允许出现的行为

- 没有复现问题便猜测原因。
- 只看代码、尺寸或单张素材，不看最终合成画面。
- 用“换颜色”“加金边”“加纹理”冒充艺术指导。
- 主视觉没有批准便批量生产按钮和图标。
- 角色、背景、UI分别好看，但不属于同一场景。
- 只检查默认状态，不检查悬停、按下、选中、焦点和快速切换。
- 让主创充当基础找茬测试员。
- 新问题出现后只修红框，不审计同类组件与上下游状态。
- 没有证据便使用“顶级”“无问题”“全部检查完成”。

## 2. 《三命无常》的艺术北极星

### 2.1 玩家第一感受

玩家进入游戏的前三秒，应感到：

> 这是一个绮丽、鲜活、可亲近的东方幻想舞台；可爱的神话英雄正等待进入一场残酷而有仪式感的三命博弈。

### 2.2 四个艺术支柱

#### A. Q版神话英雄是第一视觉核心

- 角色决定世界的亲和度、比例、细节密度和情绪温度。
- 场景与UI必须服务角色，不得用写实、阴森或过度厚重的框架压住Q版生命力。
- 英雄应像“活在这个世界中”，而不是贴在背景上的透明PNG。

#### B. 东方幻想绮丽画卷

- 关键词：云海、仙城、玉石、鎏金、织物、法器、霞光、流云、神话纹样。
- 不是泛古风，不是网页国潮，不是影楼仙侠，也不是堆砌龙纹和金边。
- 画面必须有空气、远近层次、光源方向和可供角色站立的空间。

#### C. 三命是产品独有的视觉母题

- “三”必须贯穿品牌标志、开局仪式、状态反馈和关键动效。
- 三命不是三个普通按钮，而是三种命运阶段：初命、续命、绝命。
- 三条命线汇入同一战局，视觉上必须清楚、稳定、有因果关系。

#### D. 残酷规则包裹在可亲近的表象里

- 角色可爱，但选择有重量；色彩绮丽，但绝命必须有危险感。
- 禁止全界面都喜庆、都明亮、都金灿灿，导致规则失去张力。

### 2.3 视觉关系优先级

1. 当前英雄与角色状态。
2. 核心行动“开始游戏 / 匹配状态”。
3. 三命结构与当前命数。
4. 当前战场及必要信息。
5. 英雄切换、账户、图鉴等次级操作。
6. 修为、万象、天榜、设置等低频入口。

任何低优先级元素不得通过尺寸、亮度、动画或高对比抢夺更高层级的注意力。

## 3. 视觉语言规范

### 3.1 形状语言

- 主形：圆、弧、云头、玉佩、法盘、匾额。
- 辅形：六边命纹、回纹、法器结构、绶带。
- 重要行动使用横向稳定的大形；状态节点使用圆形；次级入口使用窄型竖牌。
- 同级组件必须共享轮廓家族、圆角逻辑、边框厚度和装饰密度。

### 3.2 材质语言

- 主材质：温润青玉、旧金/鎏金、深青漆木、半透明灵光。
- 一件控件最多两种主材质加一种发光反馈。
- 金属高光必须有统一光向；禁止同屏出现不同光向的AI素材。
- 禁止在厚重栅格玉石控件中混入扁平线性图标。

### 3.3 色彩角色

- 青玉：常态、可信、秩序。
- 暖金：重要、可操作、成功、荣耀。
- 初命绿：生命与安全。
- 续命金：机会与代价。
- 绝命朱红：危险与不可逆。
- 紫色：妖异、法术、特殊角色，不作为通用系统色。

### 3.4 字体层级

- 品牌与重大仪式：有书写感的标题字体。
- 按钮、数字、状态和说明：清晰的中文黑体/宋黑混合，不用难认书法字。
- 每个组件先定义文字安全区，再放文字；禁止靠肉眼临时挪动。
- 同级标签字号、行高、字重必须一致。
- 标准文本应达到足够对比；重要小字不得依赖发光维持可读性。

### 3.5 图标语言

每个图标必须通过四项测试：

1. **语义正确**：不看文字也能大致理解。
2. **家族一致**：同样的金边厚度、玉质、透视和光向。
3. **实际尺寸可读**：在最终显示尺寸下不是一团噪点。
4. **轮廓有差异**：修为、万象、天榜、设置不能只靠内部小细节区分。

### 3.6 动态语言

- 动效必须表达：因果、状态、反馈、生命感之一。
- 高频按钮反馈应短、准、轻；不得让玩家等待动画完成。
- 环境动效慢而弱，交互动效快而明确，关键结果动效强但短。
- 三命汇流节点必须锁定在结构交点；禁止无意义漂移。
- 沿线粒子属于能量流，不得大到像独立按钮或漂浮圆球。
- 必须支持 `prefers-reduced-motion` 或等价减弱方案。

## 4. AI Agent 美术生产管线

### 阶段0：读取真源与建立约束

必读输入：

- 游戏真源文档。
- 当前版本界面和全部已有资产。
- 用户明确保留的角色、场景和交互逻辑。
- 目标分辨率、平台、性能和交付形式。

输出：一页《视觉任务简报》，至少包括玩家目标、艺术支柱、保留项、禁区、目标作品和验收标准。

### 阶段1：研究与拆解

- 至少研究 8 个相关成熟案例，其中至少 3 个为可运行游戏界面，而非仅看 Behance 概念稿。
- 每个案例只提炼可迁移规律，不直接拼贴风格。
- 建立“借鉴什么 / 不借鉴什么 / 为什么”的对照表。

### 阶段2：全页面效果图

- 先完成整页效果图或高保真合成，不先批量切按钮。
- 效果图必须真实包含角色、背景、按钮、文字、图标和主要状态。
- 至少比较两种真正不同的构图方案，不把换色称为新方案。
- 主创确认方向后，才能进入组件化。

### 阶段3：视觉系统样板

先做一组“母组件”：

- 一个主按钮及默认/悬停/按下/不可用状态。
- 一个次级入口。
- 一个英雄卡及选中状态。
- 一组3–4枚同家族图标。
- 一个弹窗/抽屉外框。

母组件通过后再批量扩展；失败则回到效果图，不在错误方向上精修。

### 阶段4：资产生产

- 动态文字不得烘焙进PNG。
- 每个PNG保留透明安全边；检查白边、黑边、色溢、断边和裁切。
- 同组状态保持相同画布、锚点和逻辑尺寸。
- 文件命名必须说明组件、用途和状态。

### 阶段5：HTML落地

- 建立设计令牌：颜色、字号、间距、圆角、边框、阴影、动效时长。
- 同类控件调用同一组件规则，不复制出多个近似版本。
- 角色、名称、属性、选中标识必须来自同一状态源。
- 动画不得推迟关键状态同步；视觉过渡和数据状态分离。

### 阶段6：运行态验收

必须在最终交付文件中逐状态截图，而不是在设计软件里验收。

## 5. 强制质量门禁

### Gate A：方向门禁

- [ ] 能用一句话说清本页要让玩家感到什么。
- [ ] 角色、背景、UI属于同一世界。
- [ ] 三命母题清晰但不过度堆砌。
- [ ] 视觉层级符合第2.3节。
- [ ] 与成熟案例的差距已被明确描述。

任一项失败：退回构图/艺术方向，不允许微调交付。

### Gate B：系统门禁

- [ ] 所有同级按钮共享同一轮廓、材质、光向和字体规则。
- [ ] 图标语义正确且实际尺寸可读。
- [ ] 文本全部在安全区内，无裁切、溢出、压装饰。
- [ ] 角色脚底与场景接触面成立。
- [ ] 账户身份与当前展示英雄在概念上明确区分。
- [ ] 角色、名称、属性和选中状态同步。

### Gate C：交互状态门禁

每个可交互组件都必须检查：

- [ ] 默认。
- [ ] 鼠标悬停。
- [ ] 按下。
- [ ] 选中。
- [ ] 键盘焦点。
- [ ] 禁用/锁定（若存在）。
- [ ] 快速重复操作。
- [ ] 状态切换中重新打开面板。

否决项：白线、黑边、跳位、缩放接缝、文字漂移、状态错配、旧Toast残留。

### Gate D：像素门禁

- [ ] 100%全页检查。
- [ ] 每个争议组件400%完整边缘扫描。
- [ ] 四角与内部接缝800%检查。
- [ ] 透明素材在黑、白、棋盘背景检查。
- [ ] 重复控件中心偏差尽量≤0.5 CSS px，最终成图≤1物理像素。
- [ ] 不以文件矩形中心代替可见图形的光学中心。

### Gate E：视口门禁

至少检查：

- [ ] 1536×1024桌面基准。
- [ ] 1100×720紧凑桌面。
- [ ] 用户当前窄视口或等价尺寸。
- [ ] 100%与125%显示缩放。
- [ ] 无横向溢出，无浏览器边缘裁切。

### Gate F：交付门禁

- [ ] 源文件与独立版同步。
- [ ] 所有图片成功加载。
- [ ] 控制台错误为0。
- [ ] 自动检测通过。
- [ ] 两轮相邻区域扩展检查没有发现新问题。
- [ ] 保存默认、悬停、按下、选中、窄屏截图作为证据。
- [ ] 明确列出仍存在的限制；不得隐瞒或用“顶级”代替说明。

## 6. 美术评审方法

### 6.1 评审顺序

1. **情绪**：第一眼是什么感觉？是否符合游戏？
2. **层级**：第一眼看到什么？是否是正确目标？
3. **构图**：角色、场景、操作是否形成整体？
4. **系统**：组件是否来自同一视觉家族？
5. **可读性**：信息是否能迅速读取？
6. **动效**：是否表达原因和结果？
7. **像素**：边缘、接缝、对齐、文字、裁切是否干净？
8. **生产性**：能否扩展到其他页面和状态？

不得从“金边有没有对齐”开始评审一个方向错误的页面，也不得用“方向不错”放过像素错误。

### 6.2 反馈格式

每条反馈必须包含：

- 现象：玩家实际看到了什么。
- 原因：层级、材质、状态或技术根因。
- 影响：破坏了什么体验。
- 修复标准：怎样才算完成。
- 证据：修复前后同尺寸截图。

禁止反馈：“不够高级”“再精致一点”“感觉不对”而不给判断依据。

## 8. 《三命无常》当前大厅专项清单

- [ ] 当前英雄站在擂台真实接触面上，脚底不漂浮。
- [ ] 角色呼吸动画不改变脚底锚点。
- [ ] 英雄名、英雄图、属性、图鉴选中完全一致。
- [ ] 玩家账户牌不被误解为当前英雄牌。
- [ ] “开始游戏”是最明显且文案直白的行动。
- [ ] 三命节点为圆形且按初命/续命/绝命清楚区分。
- [ ] 三条线各自完整汇入同一固定节点。
- [ ] 汇流节点不漂移，沿线粒子不抢眼。
- [ ] 30个席位点完整存在，激活状态可读。
- [ ] 右下角四个入口图标语义正确、材质一致、文字居中。
- [ ] 图鉴标题和关闭键避开角花安全区。
- [ ] 英雄卡默认、悬停、选中、焦点均无白边或接缝。
- [ ] 图鉴页脚不压边、不裁切。
- [ ] 图鉴打开时大厅Toast不可残留或延迟出现。
- [ ] 快速选择并立即重开图鉴时状态仍一致。

## 9. 参考依据

本手册综合并转译了以下公开资料的方法：

- EA DICE / GDC：《Building a Visual Identity: An Art Direction Framework》——艺术支柱、视觉身份以及创意、技术、市场的统一。
- GDC：《Art Direction: Graphic Design is Key》——字体、图标、色彩、图形元素与UI/菜单共同构成视觉签名。
- Riot Games Art Education：《User Interface Design》——UX与UI分工，以及一致、连贯、沉浸的游戏界面。
- Ubisoft Creative Process——用持续更新的项目愿景作为团队方向基准。
- Ubisoft Visual Design Art Director / UI Artist职责——用简报、情绪板、草图、参考和验证管理菜单、HUD与视觉反馈。
- GDC 生产资料——美术指导不仅塑造风格，也必须规划生产与技术管线；技术规范用于减少误解和返工。
- Microsoft Xbox Accessibility Guidelines——文字、图形、焦点、对比和不同情境下的可读性要求。
- Apple Human Interface Guidelines: Motion——动效必须有目的、简短准确、可减弱，不能为了动而动。
- W3C WCAG 2.2——焦点可见性、非文本对比、目标尺寸及悬停内容的基本原则。

## 10. 美术总监誓约

> 我不以语言声势代替视觉结果；不以代码正确代替成图正确；不让主创替我完成基础质检。  
> 我先建立方向，再建立系统；先验证母版，再批量生产；先复现问题，再判断根因。  
> 我对玩家最终看到的每一个像素、状态和视觉关系负责。
